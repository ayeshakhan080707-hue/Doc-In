  OBSERVER ROLE — PUBLIC + LOGGED-IN READ-ONLY ACCESS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CONCEPT
  ─────────────────────────────────────────────────────────────────
  DocIn platform ka feed aur content bina login ke bhi publicly visible hoga
  (like Twitter/X). Koi bhi aakar dekh sakta hai kya ho raha hai platform pe.

  Observer 2 tarah ka hoga:
    1. ANONYMOUS OBSERVER  — Bina account ke, sirf browser se dekh raha hai
    2. REGISTERED OBSERVER — Account bana liya lekin professional nahi hai

  Jab bhi koi restricted action karna chaye (apply, connect, post, message)
  toh upgrade prompt aayega — professional account banana hoga.

  ACCESS MATRIX
  ─────────────────────────────────────────────────────────────────

  REGISTRATION FLOW
  ─────────────────────────────────────────────────────────────────
  Signup page pe 2 options:

    Option A: "I am a Healthcare Professional"
              → Select role: Doctor / Hospital Admin / Recruiter
              → Complete professional profile
              → Full access immediately (verification badge later)

    Option B: "I want to explore DocIn"
              → Sirf email + password
              → OBSERVER role assign
              → Platform browse kar sako
              → Jab chahein upgrade karo

  ANONYMOUS USER (No Login) EXPERIENCE
  ─────────────────────────────────────────────────────────────────
  • Feed publicly visible — posts load without any authentication
  • Doctor profile pages publicly accessible
  • Jobs page publicly visible
  • Search works without login
  • Any action button (Like, Comment, Connect, Apply) pe click:
      → "Sign in to interact" prompt with Login / Register buttons
  • SEO benefit: Google index kar sakta hai public content
  • Social sharing: Post link share karo — koi bhi dekh sakta hai

  BACKEND IMPLEMENTATION PLAN
  ─────────────────────────────────────────────────────────────────

  1. User model mein OBSERVER role add karo:
     role enum: ['OBSERVER', 'DOCTOR', 'HOSPITAL_ADMIN',
                 'RECRUITER', 'CREDENTIALING_OFFICER', 'SUPER_ADMIN']

  2. New middleware — requireProfessional:
     Sirf professional roles allow karo restricted endpoints pe
     (DOCTOR, HOSPITAL_ADMIN, RECRUITER, CREDENTIALING_OFFICER, SUPER_ADMIN)

  3. Public endpoints (no auth needed):
     GET  /api/posts/feed          → Public feed
     GET  /api/recruiter/jobs      → Jobs listing
     GET  /api/doctor/profile/:id  → Public doctor profile
     GET  /api/search              → Global search

  4. Observer-allowed endpoints (auth optional):
     GET  /api/chat/notifications  → If logged in as observer
     GET  /api/network/recommendations → View only

  5. Professional-only endpoints (requireProfessional middleware):
     POST /api/posts               → Create post
     POST /api/posts/:id/like      → Like post
     POST /api/posts/:id/comment   → Comment
     POST /api/network/request     → Send connection
     POST /api/chat/messages       → Send message
     POST /api/jobs/:id/apply      → Apply to job
     POST /api/credentials/upload  → Upload credential

  FRONTEND IMPLEMENTATION PLAN
  ─────────────────────────────────────────────────────────────────

  1. App.tsx changes:
     - Feed, Jobs, Search, Doctor Profile → Public routes (no ProtectedRoute)
     - Action buttons → Check auth before allowing interaction

  2. New hook — useProfessionalGuard():
     const { requirePro, showUpgradeModal } = useProfessionalGuard();
     // Usage: onClick={() => requirePro(() => handleApply(job))}
     // If observer/no login → show upgrade modal
     // If professional → run the action

  3. UpgradeModal component:
     - Shows when observer tries restricted action
     - Role selection: Doctor / Hospital / Recruiter
     - Redirects to register with pre-selected role

  4. Navbar update:
     - Jab logged out ho: "Sign In" + "Join DocIn" buttons visible
     - Feed aur public pages bina login accessible

  5. PostCard update:
     - Like/Comment buttons: bina login click → Login prompt
     - Observer login → Upgrade prompt

  SUPERADMIN OBSERVER MANAGEMENT
  ─────────────────────────────────────────────────────────────────
  • Observer users list dekh sakta hai
  • Observer ka role upgrade kar sakta hai (to Doctor/Hospital/etc.)
  • Observer account suspend kar sakta hai (spam prevention)
  • Observer conversion rate analytics:
      Total Observers → Upgraded to Professional (% conversion)
  • Observers who viewed most content (engagement tracking)

  BENEFITS OF THIS APPROACH
  ─────────────────────────────────────────────────────────────────
  ✅ SEO — Google public feed index karta hai → more organic traffic
  ✅ Low friction — Koi bhi aa ke dekh sakta hai, pressure nahi signup ka
  ✅ Conversion funnel — Observer → action try kare → upgrade naturally
  ✅ Viral sharing — Posts share ho sakte hain publicly
  ✅ Genuine users — Jo actually kaam karna chahte hain wo upgrade karte hain
  ✅ Spam prevention — Observers restricted hain, fake activity nahi
  ✅ Platform credibility — Public visible content trust build karta hai

SuperAdmin ka ek dedicated control panel hoga jisme yeh sab kuch hoga:

  USER MANAGEMENT
  ─────────────────────────────────────────────────────────────────
  • Har user ko dekh sakta hai (search, filter by role/status/tier)
  • User create kar sakta hai (kisi bhi role ka)
  • User ka role change kar sakta hai
  • User suspend / activate / delete kar sakta hai
  • Kisi bhi user ki clinical verified seal grant ya revoke kar sakta hai
  • Kisi bhi user ko Premium Gold de ya wapas le sakta hai
  • User ki complete profile dekh sakta hai (posts, credentials, connections)
  • Bulk actions: multiple users select karke suspend/activate/delete

  CREDENTIAL VERIFICATION MANAGEMENT
  ─────────────────────────────────────────────────────────────────
  • Poora verification queue dekh sakta hai (SUBMITTED / UNDER_REVIEW)
  • Kisi bhi credential approve ya reject kar sakta hai
  • Credentialing officers assign kar sakta hai to specific documents
  • Credential history + audit trail dekh sakta hai
  • Fake/fraud credentials flag kar sakta hai
  • Verification stats: daily/weekly approvals, rejections, pending count

  CONTENT MODERATION
  ─────────────────────────────────────────────────────────────────
  • Koi bhi post delete kar sakta hai
  • PHI-violating posts flag karna aur auto-remove
  • User ko post karne se temporarily ban kar sakta hai
  • Reported posts queue manage kar sakta hai
  • Comments moderation
  • Reported users queue

  JOB POSTING MANAGEMENT
  ─────────────────────────────────────────────────────────────────
  • Koi bhi job posting dekh, edit, close ya delete kar sakta hai
  • Fake job postings remove kar sakta hai
  • Job applications statistics dekh sakta hai
  • Hospital/Recruiter ki job posting rights suspend kar sakta hai

  MESSAGING OVERSIGHT
  ─────────────────────────────────────────────────────────────────
  • Reported conversations flag dekh sakta hai
  • Spam/abusive messaging users ko ban kar sakta hai
  • (Note: Private messages encrypted — full content access nahi for privacy)

  • Messaging volume
  • Top active users
  • Revenue metrics (Gold subscriptions)

  • View all Gold members list
  • Revenue report

  AUDIT LOGS
